# ทำเสียงให้เข้ากับท่า

เสียงจะรู้สึกใช่ เมื่อมันลงตรงเฟรมที่ร่างกาย*ทำอะไรบางอย่าง*พอดี ให้หาเฟรมเหล่านั้นจากข้อมูลท่า ไม่ใช่ใช้หูเดา
ข้อ 0 คือเครื่องมือพร้อมใช้ · ที่เหลือคือวิธีคิดและรูปแบบไฟล์

## 0. เครื่องมือ (v1.1)

เสียงเตรียมมาเอง เครื่องมือช่วยหาว่าต้องเล่น**ตอนไหน**

```bash
# หลังจาก: npm run motion -- dump  +  npm run motion -- rig ...   (ดูหน้า ทำ Animation จาก FBX)
npm run cues -- Hero.rig.json        # → workspace/cues/Hero.json + Hero.html (ไทม์ไลน์ เส้นกราฟ + จุดเสียง ทุกท่า)
```

- จังหวะที่หาได้: **step** (เท้าลงมาถึงช่วงพื้นหลังจากยกขึ้น — ใช้ได้กับท่าวิ่งอยู่กับที่) · **swing** (มือเร็วสุด วางก่อนจุดสูงสุด 0.04 วิ)
  · **head** (หัวพุ่ง) · **tail** (ปลายหางเร็วสุด) · **roar** (อ้าปาก ≥ 0.5 วิ มีเวลาจบ) / **snap** (อ้าปากสั้นๆ) · **drop** (ตัวล้มลงและต่ำลงจริง)
  เกณฑ์ทุกตัวเทียบกับขนาดตัว ตัวเล็กหรือตัวใหญ่ใช้ค่าเดียวกันได้
- ตรวจเฉพาะส่วนที่มีในไฟล์ rig · ชื่อเสียงมาจาก `"sounds"` ในไฟล์ rig — เปลี่ยนเป็นชื่อไฟล์เสียงของคุณเองได้
- ไฟล์ cue เป็นจุดเริ่มต้น: **เปิดหน้าดู FBX** เปิด *เสียงติ๊กตามจุด* เล่นช้า ×0.25 แล้วแก้เวลาเองตรงที่ยังไม่ลง
- **เล่นใน three.js** ด้วย `models/cue_player.js`:
  ```js
  import { CuePlayer } from '../models/cue_player.js';
  const player = new CuePlayer();
  await player.load({ step:['sfx/step1.wav', 'sfx/step2.wav'], whoosh:['sfx/whoosh.wav'],
                      roar:{ start:'sfx/roar_in.wav', loop:'sfx/roar_loop.wav', end:'sfx/roar_out.wav' } });
  player.setCues(await (await fetch('workspace/cues/Hero.json')).json());
  button.onclick = () => player.unlock();                  // เบราว์เซอร์ต้องมีการคลิก 1 ครั้งก่อนเล่นเสียง
  // ทุกเฟรม:
  player.update('Walk', prevTime, time, { plan });         // plan = timePlan(...) ถ้าตัดหรือเร่งท่า
  ```
  ใส่เป็น array = สุ่มเสียง · `{start, loop, end}` + cue ที่มีเวลาจบ = เสียงต่อเนื่อง

## 1. หาจังหวะ

จากตำแหน่งกระดูกทุกเฟรม (ดู [ทำ Animation จาก FBX](animation.md))

| เสียง | จังหวะ | วิธีจับ |
|---|---|---|
| ฝีเท้า | เท้าแตะพื้น | ความสูงเท้ากลับลงมาอยู่ในช่วงต่ำสุด 20 % หลังจากยกขึ้น (ท่าวิ่งอยู่กับที่ เท้าที่ลงพื้นยังเลื่อนอยู่ ดูความเร็วอย่างเดียวจะพลาด) |
| สวิง / ฟึ่บ | ช่วงสวิงเร็วสุด | ความเร็วสูงสุดของมือ / ปลายอาวุธ (เริ่มเสียงก่อนจุดพีคนิดหนึ่ง) |
| กระแทก | สวิงหยุด | ความเร็วปลายอาวุธตกฮวบหลังจุดพีค |
| คำราม / เสียงพูด | ปากอ้า | มุมกรามเกินค่าที่ตั้ง · ความยาว = อ้าค้างนานแค่ไหน |
| ล้มกระแทกพื้น | ตัวถึงพื้น | ความสูงสะโพกต่ำสุดหลังร่วงเร็ว |
| กระพือปีก | จังหวะตีลง | ความเร็วแนวดิ่งของข้อมือปีกติดลบมากสุด |

## 2. ไฟล์ cue

1 ไฟล์ JSON ต่อโมเดล cue แยกตามท่า หน่วยวินาที:

```json
{
  "clips": {
    "attack": { "len": 1.8, "cues": [ { "t": 0.42, "sfx": "whoosh" }, { "t": 0.61, "sfx": "impact" } ] },
    "walk":   { "len": 1.0, "loop": true, "cues": [ { "t": 0.12, "sfx": "step" }, { "t": 0.62, "sfx": "step" } ] }
  }
}
```

- **สุ่มเสียง:** ตั้งชื่อเป็นกลุ่ม (`step`) แล้วสุ่ม 1 จากหลายไฟล์ทุกครั้ง เสียงเดิมซ้ำๆ จะฟังเป็นเครื่องจักร
- **ท่าที่ถูกตัด / เร่ง:** ตัดช่วง `[a, b]` ออก หรือเร่งช่วงไหน ให้เลื่อน cue หลังจากนั้นเท่ากัน
  เก็บไฟล์ cue เป็น*เวลาของท่าต้นฉบับ*เสมอ แล้วค่อยแปลงตอนเล่น ต้นฉบับจะใช้ได้ตลอด

## 3. เสียงต่อเนื่อง

คำรามยาวหรือเสียงชาร์จพลัง ไม่ควรเป็นไฟล์เดียวที่ยืดออก ให้ใช้ **ต้นเสียง + ช่วงวน + ท้ายเสียง**
เริ่มที่ cue แล้ววนช่วงกลางแบบไร้รอยต่อระหว่างที่ท่าค้าง (ปากอ้า · กำลังชาร์จ) จากนั้นปล่อยท้ายเสียงตอนท่าจบ
ความยาวช่วงค้างเอามาจากท่า (ปากอ้าเกินค่าที่ตั้งนานแค่ไหน)

## 4. Sound Map ให้ทีม

โปรแกรมเมอร์ของ engine อ่านตารางง่ายกว่าอ่านโค้ด:

| ท่า | เวลา (วิ) | เสียง | หมายเหตุ |
|---|---|---|---|
| attack | 0.42 | whoosh | สุ่ม 1 ใน 3 |
| attack | 0.61 | impact | |
| roar | 0.30 → 2.10 | roar (sustain) | วนระหว่างปากอ้า |

engine ใส่เป็น Animation Event ตามเวลาในตารางได้เลย
