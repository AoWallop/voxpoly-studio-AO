# แสงเงาการ์ตูนและภาระการวาด

[English](../en/look-and-performance.md)

โมดูลเล็ก 2 ตัวที่ใช้ได้กับหน้า three.js หรือเกมไหนก็ได้ ตัวแรกเปิดแสงเงาแบบการ์ตูนให้ทั้งฉาก ตัวที่สองแสดงว่าฉากนี้วาดหนักแค่ไหน
ทั้งคู่ต้องการแค่ `three`

## 1. แสงเงาการ์ตูน — `models/toon.js`

GLB และ FBX เก็บได้แค่วัสดุมาตรฐาน แสงเงาการ์ตูนจึงต้องใส่ตอนแสดงผล เรียกครั้งเดียวแปลงได้ทั้งฉาก
รวมถึงของที่เพิ่มเข้ามาทีหลังและตัวละครที่มี skin

```js
import { applyToon } from './models/toon.js';
const T = applyToon(scene, renderer, { steps: 2, dark: .55, outline: 2 });
function loop(){ T.update(); renderer.render(scene, camera); }
T.set(false);   // ปิดเทียบกับวัสดุเดิม
```

| ค่า | ความหมาย |
|---|---|
| `steps` | จำนวนขั้นแสงเงา 2–4 (2 = สองโทนแบบคลาสสิก) |
| `dark` | ความสว่างของขั้นมืดสุด 0–1 |
| `outline` | ความหนาเส้นขอบเป็น**พิกเซลบนจอ** (0 = ไม่มี) · `outlineColor` |
| `outlineMax` | เส้นขอบหนาสุดเป็น**เมตร** (ค่าเริ่ม 0.006) ของที่อยู่ไกลหรือเล็กจะได้เส้นบาง ไม่ดำเป็นก้อน |
| `unlitDark` | ขั้นมืดของโมเดล Unlit ที่ระบายเงาไว้ในสีแล้ว (ค่าเริ่ม 0.8 กันเงาซ้อนจนมืด) |
| `filter(mesh)` / `outlineFilter(mesh)` | คืน false = ไม่แปลงชิ้นนั้น / ไม่ใส่เส้นขอบให้ชิ้นนั้น |

**สิ่งที่ไม่แปลง:** ของเรืองแสง (emissive) · ของที่ไม่ผ่าน tone map (UI ป้าย ลำแสง) · BackSide (ท้องฟ้า) · เส้นและจุด ·
วัสดุโปร่งใสมาก · particle (`depthWrite: false`) · ทุกอย่างที่อยู่ใต้ object ที่ใส่ `userData.noToon = true`

**เส้นขอบทำงานยังไง:** วาด mesh ซ้ำอีกรอบเฉพาะด้านหลัง แล้วดันออกตาม normal บนจอ
mesh ที่มี skin จะได้เส้นขอบที่มี skin ด้วย จึงขยับตามท่า

**ต้นทุนและข้อจำกัด**
- ทุกชิ้นที่มีเส้นขอบ = draw call เพิ่ม 1 ครั้ง และวาดสามเหลี่ยมซ้ำสองรอบ ใช้ `outlineFilter` ข้ามของชิ้นเล็ก
- โมเดลขอบคม (normal แบนแยกจุดทุกมุม) เส้นขอบจะมีช่องเล็กๆ ตรงมุม ใช้ normal แบบเนียนหรือ weighted normal จะไม่เป็น
- วัสดุ toon ไม่สนค่า metalness / roughness โลหะจะดูเหมือนสีทา ให้ใช้สีที่สว่างกว่าแทน

## 2. ตัววัดภาระการวาด — `models/perf.js`

`nav.js` โหลดให้ทุกหน้าของสตูดิโอ มุมขวาล่างจะแสดง **draw call**, **สามเหลี่ยม** และ **fps** กด **P** เพื่อซ่อน
สคริปต์และการตรวจ QC อ่านค่าได้จาก `window.__perf` (`draws`, `tris`, `fps`, `peakDraws`, `peakTris`)

นับจากคำสั่งวาดจริงของ WebGL จึงรวมเงา เส้นขอบ toon และหลาย canvas ไว้ด้วย
สี: เขียว = อยู่ในงบ · เหลือง = ไม่เกิน 1.5 เท่า · แดง = เกินงบ

| งบ (แว่น VR แบบไม่ต่อคอม) | |
|---|---|
| draw call ต่อเฟรม | ประมาณ 80 |
| สามเหลี่ยมต่อเฟรม | ประมาณ 150,000 |

draw call มักเป็นตัวที่ทำให้กระตุกก่อนสามเหลี่ยม: ชิ้นเล็ก 300 ชิ้น ชิ้นละ 20 สามเหลี่ยม หนักกว่า mesh เดียว 6,000 สามเหลี่ยมมาก
รวมชิ้นที่อยู่นิ่งและใช้วัสดุเดียวกันเข้าด้วยกัน และระวังเส้นขอบกับไฟที่ทำเงา (แต่ละอย่างคูณจำนวน draw)

ใช้ในหน้าของเราเอง: `import './models/perf.js';` ครั้งเดียว จะก่อนหรือหลังสร้าง renderer ก็ได้
เบราว์เซอร์แบบ headless ให้ค่า fps ที่เชื่อไม่ได้ แต่จำนวน draw กับสามเหลี่ยมเชื่อได้
